# Provenance

Implementation source, synthetic fixtures, interface copy, and architecture documents were created for this standalone portfolio project. The KEV workflow additionally accepts attributed public CISA data. No private repository, employer system, customer log, credential, proprietary document, or copied company implementation was used.

The `search-index` service, incident counters, tickets, roles, tenants, and action text are synthetic. Ticket identifiers are generated during execution. The observed fault report is generated by executing `scripts/evaluate.mjs`; it records actual local results for that synthetic system and does not claim a general benchmark or production result.

The runtime planner is deterministic. The runtime makes no hidden model or embedding calls. Its optional `kev-draft/v1` input records a separately generated model draft, prompt hash, evidence hash, citations, model/provider and measured usage. Supplied citations are checked for membership, not semantic entailment; the draft remains an unverified suggestion. Missing drafts are explicitly recorded as `not-used`.

## Public KEV evidence

The real review integration consumes `kev-evidence/v1` exported by [Policy RAG Lab](https://github.com/demier-demier/policy-rag-lab), with source URL, retrieval time, catalog version, snapshot SHA-256, and individual text hashes. The primary public dataset is [CISA's Known Exploited Vulnerabilities catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog); commit-pinned files from [CISA's official KEV repository](https://github.com/cisagov/kev-data) are also accepted. That repository publishes the data under [CC0-1.0](https://github.com/cisagov/kev-data/blob/develop/LICENSE).

Catalog listing is evidence of known exploitation, not proof that an analyst's assets are affected. CISA due dates are retained as source fields; the report does not apply them as universal organizational deadlines. A source URL and matching hashes prove internal consistency, not origin authentication; the offline runtime trusts the imported snapshot and preserves its provenance for independent checking.

Unit-test KEV records are explicitly synthetic fixtures. Any committed observed KEV deliverable is generated from the attributed public packet, not from those fixtures. Browser ticket workflows remain synthetic and separate from public-data file delivery.

Dependencies are pinned in `package.json` and `package-lock.json`:

- `@noble/hashes`: SHA-256 implementation used by both environments.
- TypeScript, esbuild, Prettier, and Node type declarations: build/type/format tooling.
- `fake-indexeddb`: adapter contract tests only; the browser demo uses the native API.
- Node `node:sqlite`: built-in SQLite adapter and separate synthetic external store.
